//Pointer

#1. Void pointer
-> special pointer that can point to any data type
int val = 100;
void *ptr;
ptr = &val;

#2. function pointer
-> store address of a function
-> used to implement callback functions, event handling, dynamic function
int (*fptr)(int, int);
fptr = &add; //1
fptr = &sub; //2
printf("%d", fptr(10, 5));

-> Callback function
void execute(int (*func)(int, int))
{
    int result = func(10, 5);
    printf("%d\n", result);
}
execute(add);
execute(sub);

#3. Constant Pointers vs Pointers to Constants

-> Pointer to constant data - data can't modify
const int *ptr = &val;
//*ptr = 50 -> ERROR: cannot modify through ptr

-> Constant pointer - Pointer itself can't be reassigned
int *const ptr = val;

//ptr = &another; -> Error: Cannot reassigned pointer

-> Constant pointer to Constant data
const int *const ptr = &val;

//Volatile 
#1. Problem
-> Compiler can optimized by cache data into register CPU instead of read every cycle from RAM
-> If the variable is changed by others(ISR, HW, register, ...) -> the variable data cannot be change because the compiler optimization

#2. volatile solve
-> Tell to the compiler that the variable can be changed everytime
-> Have to read from RAM each time, not use cache value

#3. Limitation of volatile
-> Cannot be safety for race condition

Bước 1: main() bắt đầu counter++
         → LOAD R0, [counter]     ; R0 = 5 (giá trị hiện tại)
         
Bước 2: NGẮT XẢY RA ngay đây, trước khi main kịp ADD/STORE
         → CPU nhảy vào ISR
         → ISR chạy xong counter++ hoàn chỉnh: đọc 5, +1, ghi lại → counter = 6

Bước 3: CPU quay lại main(), tiếp tục dở dang từ chỗ đã dừng
         → ADD R0, R0, #1         ; R0 = 5 + 1 = 6 (dùng giá trị CŨ đã load ở bước 1!)
         → STORE [counter], R0    ; ghi 6 vào counter

Kết quả: counter = 6, nhưng đáng lẽ phải là 7 (vì cả ISR và main đều +1 một lần).

#4. Solve "Race Condition"
-> Using atomic/mutex/spinlock
-> temporary disable/enable interrupt
   __disable_irq() / __enable_irq() -> prevent ISR process during critical section


//ISR-safe coding
-> Rule: ISR should run as fast as possible
-> Why?: If the ISR is stuck then the other ISR is miss and the critical section cannot be process on time

#1. 3 things should prevent during ISR
-> malloc/free (uboresictable timing function) -> bad for code need process as fast as possible
-> Blocking call: delay(), semaphore/mutex (need time to wait the other release lock) -> ISR will wait and then the entire operation are locked
-> Complex IO:: printf()

//Alignment

-> CPUs read RAM in fixed-size blocks, misaligned variables can be slower or cause a crash (bus fault) on some architectures (e.g. ARM Cortex-M).
-> The compiler automatically inserts padding so each field is properly aligned.
type:      byte 0        [1 byte]
padding:   byte 1-3       [3 bytes, so value aligns to 4]
value:     byte 4-7       [4 bytes]
id:        byte 8-9       [2 bytes]
checksum:  byte 10        [1 byte]
padding:   byte 11        [1 byte, trailing — rounds 11→12]

//Endianness

-> Little-endian (ARM Cortex-M, x86): least significant byte (LSB) stored at the lowest address
-> Big-endian (many network protocols): most significant byte (MSB) stored at the lowest address


//Struct

-> Struct stores all fields simultaneously, each with its own memory region


//Union - fields share the same memory

-> All fields in a union overlap the same address
-> Union's size equals the size of its largest field

union Value {
    uint8_t  byte;
    uint16_t half;
    uint32_t word;
};

-> sizeof(Value) = 4 bytes (Matching the largest field)
-> Common use in embedded:

union Option {
    uint16_t option_value;
    uint8_t dry;
    uint8_t spin;
};


//Bitfield

struct StatusRegister {
    uint8_t enable   : 1;   // 1 bit            -> Instead of reg |= (1 << 0);
    uint8_t mode     : 2;   // 2 bits
    uint8_t reserved : 3;   // 3 bits
    uint8_t error    : 2;   // 2 bits
};  // total: 8 bits = exactly 1 byte

-> Disadvantages of bitfield:
    1. The compiler can decide what bit are first
        Compiler A:
            a -> bit0
            b -> bit1
        Compiler B:
            a -> bit1
            b -> bit0
    2. Affects by  big-endian and little-endian


//Packing - Forcing the compiler to skip padding

struct __attribute__((packed)) Packet {
    char type;
    float value;
    short id;
    char checksum;
};
-> Not packed: 12 bytes
-> Packed: exactly 1+4+2+1 = 8 bytes, no padding

-> When a struct needs to match a fixed data format byte-for-byte (network protocol, file format, data received via SPI/I2C from another device)
-> Some CPU core dont support for unaligned data
-> Packing can affect to the CPU efficiency
